# MoxToGame v12.63 — AUDIT-01 REPORT

## Mission

**AUDIT-01 — Validation générique des cibles trop permissive**.

Objectif : faire respecter, au point d'entrée canonique de validation (`NativeEngine.#isLegalTarget`), la restriction déclarée par `effect.target`, sans modifier les définitions de cartes ni les handlers d'effets.

## Base auditée

Base de cartes actuelle : **985 cartes**.

Après vérification directe de `src/data/cards-database.js`, il existe actuellement **68 cartes avec `effect.target` défini**, réparties sur **18 valeurs distinctes**. Cette base ne correspond plus exactement aux comptages fournis dans le prompt initial : le rapport utilise les valeurs réellement présentes dans le dépôt v12.62.

Parmi elles, **39 cartes** ont `effectStatus: "implemented"` et aucune n'a actuellement `effectStatus: "functional"` tout en ayant `effect.target` défini. Les 39 ont été vérifiées individuellement par le test de non-régression global.

## Reproduction avant correction

Le test `tests/test-v12-63-target-type-restrictions.mjs` a été préparé contre le comportement existant, puis exécuté avec l'ancien `#isLegalTarget`.

Échec observé avant correction :

```text
AssertionError [ERR_ASSERTION]: Missing expected exception: creature: terrain rejeté
```

C'était la reproduction attendue : avec `effect.target: "creature"`, un terrain était encore accepté parce que la validation ne regardait que `effect.type` et la liste large de permanents.

## Correction

### Fichier moteur modifié

- `src/core/native-engine.js`

### Fichier moteur non touché

- `combat.js`
- `atomic-effects.js`
- `cards-database.js`
- aucun handler d'effet

### Implémentation

Une fonction générique exportée a été ajoutée :

```js
matchesTargetRestriction(state, perm, targetRestriction, combatState, controller)
```

Elle calcule les **caractéristiques effectives** via `calculateCharacteristics()` avant de tester les types. Cela évite de dépendre uniquement de `perm.type` imprimé.

La restriction est appliquée dans `#isLegalTarget`, après résolution du candidat dans la liste existante de `getValidTargets`. Le contrat existant de `getValidTargets(effectType, controller)` est donc conservé : son rôle reste de fournir le domaine large correspondant à l'action ; `#isLegalTarget` est le filtre canonique de légalité lorsque `effect.target` est explicitement déclaré.

La recherche du candidat a également été durcie : un `targetInfo` sans `side` ne peut plus matcher arbitrairement le premier permanent uniquement parce que `kind` et `side` sont tous deux `undefined`. Les références `uid`, `id`, `perm.uid` et `perm.objectId` sont comparées explicitement et sans égalité accidentelle sur `undefined`.

### Valeurs contextuelles supplémentaires rencontrées dans les définitions/triggers

`killer` et `enchanted` sont également rencontrés dans la base dans des effets déclenchés/contextuels. Ils ne constituent pas des domaines de sélection de cible utilisateur génériques : leur résolution dépend du contexte du trigger/source. Le matcher ne leur invente donc pas une règle de ciblage autonome ; ils restent acceptés au niveau permanent lorsqu'un contexte de résolution leur fournit déjà une référence.

Aucune autre valeur de `effect.target` n'a été trouvée dans la base actuelle.

## Caractéristiques effectives

Le matcher appelle `calculateCharacteristics(state, perm)`. Un test dédié vérifie qu'un changement de type continu peut modifier le résultat de la restriction : une créature dont le type effectif devient `Artifact` est acceptée par `artifact` et rejetée par `creature`.

Aucune modification de `continuous-effects.js` n'a été nécessaire.

## Régressions existantes révélées par le correctif

Le nouveau contrôle a révélé deux fixtures de tests existantes qui utilisaient une simple propriété `attacking=true` au lieu d'un état de combat réel alors que la base déclare `attackingOrBlockingCreature`.

Les tests ont été réalignés sur le contrat moteur :

- `tests/test-v12-16-cat-c-e2e.mjs` — scénario Pirate Ship ;
- `tests/test-v12-46-cartes-batch2-simple.mjs` — scénario Crimson Manticore.

Aucun code moteur de combat n'a été modifié.

### Cas particulier : Pirate Ship

Une vérification externe du texte historique/Oracle confirme que **Pirate Ship** vise normalement une « target creature or player », et non une créature exclusivement attaquante/bloqueuse. citeturn1search0turn1search3

La base locale contient cependant actuellement :

```json
{"type":"damage","amount":2,"target":"attackingOrBlockingCreature"}
```

Cette incohérence est **hors périmètre**, puisque la mission interdit de modifier `cards-database.js`. Le test existant a donc été adapté pour respecter la déclaration actuellement présente dans la base, et le rapport signale explicitement la divergence Oracle/base. Une future mission de correction de données devra traiter Pirate Ship ; le correctif générique v12.63 ne contient aucune exception au nom de la carte.

## Périmètre final / risques résiduels

1. `getValidTargets(effectType, controller)` conserve volontairement son domaine large historique ; le filtrage `effect.target` est effectué au point de validation canonique `#isLegalTarget`, conformément à l'option explicitement autorisée par la mission.
2. Les valeurs contextuelles `killer` et `enchanted` dépendent de triggers/Auras et ne sont pas transformées en restrictions génériques inventées.
3. `Siren's Call` (`opponentsCreatures`) est un cas de modèle de données collectif ; son handler/`needsTarget` n'a pas été modifié, conformément au périmètre.
4. `Pirate Ship` possède une déclaration locale incompatible avec son texte Oracle ; aucune exception carte-par-carte n'a été introduite.
5. Les 39 cartes certifiées avec `effect.target` ont toutes été exercées individuellement par la régression automatique. Les autres valeurs de `effect.target` présentes dans la base concernent des cartes non certifiées ou des contextes non génériques et sont listées ci-dessus.

## Conclusion

**AUDIT-01 v12.63 est validé.**

Le moteur ne traite plus `effect.type` comme seule information de domaine : lorsqu'un effet déclare explicitement une restriction de cible, celle-ci est maintenant vérifiée génériquement sur les caractéristiques effectives du permanent et, lorsque nécessaire, sur l'état réel du combat.
