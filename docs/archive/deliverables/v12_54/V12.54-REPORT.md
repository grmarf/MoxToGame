# MoxToGame v12.54 — Régénération vs endurance ≤ 0

## Base et validation initiale

- Base : MoxToGame v12.53 (livraison v12.53 mana burn).
- `npm test` avant modification : exit 0.
- 118 fichiers de test présents avant ajout du test v12.54.

## Correctif

`src/core/state-based-actions.js`, `#checkCreatureDeath` sépare désormais explicitement les deux causes :

- 704.5f — endurance effective ≤ 0 : `toDestroy.push(perm)` immédiatement ; `regenShield` n'est ni consulté ni consommé.
- 704.5g — blessures létales : le comportement existant de régénération est conservé (consommation du bouclier, retrait des blessures, engagement et événement `regenerationUsed`).

Aucune autre logique du moteur n'a été modifiée.

## Test E2E

`tests/test-v12-54-regen-vs-zero-toughness.mjs` utilise `GameFacade` et un vrai dispatch `CAST_SPELL`/`RESOLVE_STACK` afin de provoquer les vérifications SBA.

1. Dégâts létaux + bouclier : la créature survit et le bouclier est consommé.
2. Endurance fixée synthétiquement à 0 + bouclier + aucune blessure : la créature va au cimetière et le bouclier n'est pas consommé avant le changement de zone.
3. Endurance 0 + blessures marquées + bouclier : la créature va au cimetière.

Le test utilise volontairement une réduction synthétique directe de l'endurance pour isoler 704.5f. La voie existante de placement de marqueurs `-1/-1` ne réduit actuellement pas l'endurance calculée dans ce runtime ; la corriger aurait dépassé la portée du prompt.

Après changement de zone, `ZoneManager` attribue une nouvelle identité (`uid`) à l'objet en cimetière ; le test vérifie donc `previousUid`, sans modifier ce mécanisme existant.

## Mutation

Retour temporaire à la condition fusionnée d'origine : le test 2 échoue (le bouclier est consommé et la créature est sauvée). Le correctif a été restauré.
