# MoxToGame v12.43 — ChooseColor Continuation Report

## Scope

Prompt 09: integrate the existing `chooseColor` effect with the v12.41 continuation mechanism. No other choice mechanism, combat, AI, TurnManager, deckbuilder, or general rules were modified.

## Baseline

The v12.42 package was used as the starting point. The existing continuation path was inspected in `ChoiceService`, `StackController`, and the choice effect registry.

## Important discovery

The card database contains no card whose primary effect is explicitly `{ type: 'chooseColor' }`. Therefore it was not possible to honestly select an existing database card using that exact effect without inventing a card mapping. The real engine effect handler itself was used as the reference scenario instead. `Black Lotus` has `chooseColorAmount`, but that is a mana-ability color choice implemented separately and was intentionally not conflated with `chooseColor`.

## Defect

The existing `chooseColor` handler called `ctx.api.choose(...)` without supplying a continuation. Consequently a human/UI choice could become pending, but the effect had no registered resume operation to apply the selected color after `ChoiceService.resolve()`.

## Fix

`chooseColor` now supplies an `applyChoice` continuation to `ctx.api.choose()`. The continuation:

- validates that the returned value is one of the configured canonical options;
- writes `chosenColor` on the current `sourceCard` when present;
- resolves an optional target again from its runtime identity before writing `chosenColor`;
- returns the chosen canonical color.

Synchronous chooser mode is also handled explicitly: when `ChoiceService` returns a value immediately, `chooseColor` applies it directly because `ChoiceService.request()` does not invoke continuations on the synchronous path.

## Canonical values tested

`W`, `U`, `B`, `R`, `G`.

Invalid `X` is rejected and leaves the choice pending.

## TDD test

`tests/test-v12-43-choose-color-continuation.mjs`

- pause while waiting for UI choice;
- no premature source mutation;

- resume after `ChoiceService.resolve()`;
