# MoxToGame V12.60 — BUG-02 report

## Statut
**Mission BUG-02 traitée et testée avec succès pour le seul handler autorisé : `damageAndGain`.**

Le dépôt fourni affichait `package.json` en version `12.46.0`; ce numéro n'a pas été modifié.

## Preuve de reproduction et correction

### Site réellement corrigé
`src/core/effects/atomic-effects.js:434-456`, handler `damageAndGain`.

Avant correction, la branche joueur faisait une mutation directe :

```js
state[side].life -= amount;
state[controllerKey].life += amount;
```

Les dégâts contournaient donc `ReplacementService` et une prévention active ne pouvait pas les arrêter.

Correction minimale effectuée dans ce seul handler :

- appel obligatoire à `api.applyDamageToPlayer(side, amount, {...})` ;
- couleur de source transmise via `sourceCard?.color?.[0]` ;
- source et méta `effect: 'damageAndGain'` transmis ;
- gain du contrôleur calculé à partir de `result.amount`, c'est-à-dire des dégâts effectivement infligés après remplacement/prévention.

### Test créé
`tests/test-v12-60-damageandgain-replacement.mjs`

Le test vérifie la carte réelle qui utilise `damageAndGain` dans la base : **Psionic Blast** (`src/data/cards-database.js:2109-2112`). Il installe un bouclier de prévention bleu actif, lance réellement la carte contre le joueur protégé, puis vérifie :

- les 4 dégâts sont entièrement prévenus ;
- le contrôleur ne reçoit aucun gain correspondant aux dégâts prévenus ;
- le bouclier one-shot est consommé.

### Preuve d'exécution

Commande demandée :

```text
node tests/test-v12-60-damageandgain-replacement.mjs
```

Résultat :

```text
OK V12.60 BUG-02: damageAndGain passe par ReplacementService et le gain suit les dégâts réellement infligés
```

Commande intégrale :

```text

```

Résultat : **exit 0**, tous les tests passent, y compris les tests existants de Psionic Blast et les tests V12.57→V12.60 présents dans le dépôt.

Le dépôt contient **126 fichiers `.mjs` dans `tests/`** après ajout du nouveau test.

## Vérification Oracle

La carte réelle identifiée est **Psionic Blast**. La source externe consultée donne l'Oracle moderne « deals 4 damage to target creature or player and 2 damage to you », et non « vous gagnez 4 PV ». citeturn0search2turn0search3

La base locale de MoxToGame contient toutefois actuellement une modélisation différente (`damageAndGain`, `amount: 4`, `gain: 4`). Cette divergence est antérieure à cette mission et **`cards-database.js` était explicitement interdit de modification**. La présente mission ne corrige donc pas cette divergence Oracle/base ; le test BUG-02 valide exclusivement le comportement du pipeline de prévention pour le mécanisme actuellement représenté par `damageAndGain`.

### Divergence détectée dans le cadrage fourni : `atomic-effects.js:155`

Le cadrage fourni classait ce site parmi les sites déjà corrects. La lecture du code réellement livré montre actuellement :

```js
for (const side of ['player','ai']) {
  const life = ctx.api.replaceDamageLifeLoss
    ? ctx.api.replaceDamageLifeLoss(side, amount, { source: ctx.sourceCard })
    : { loss: amount };
  ctx.api.state[side].life -= life.loss;
}
```

Ce chemin **n'appelle pas `applyDamageToPlayer` et ne passe donc pas par `preventDamage`**. Dans l'implémentation actuelle de `ReplacementService`, `replaceDamageLifeLoss()` ne réalise pas la prévention de dégâts par bouclier/couleur.

Conformément à la règle absolue de périmètre, **ce site n'a pas été modifié**, car `damageAllCreaturesAndPlayers` est explicitement hors du handler autorisé. Il doit faire l'objet d'une mission séparée si ce comportement est confirmé comme bug de règles. Il serait incorrect de le déclarer « corrigé » dans BUG-02.

### Sites qui sont des pertes de vie, pas des dégâts

Ils restent volontairement inchangés :

- `src/core/effects/token-historical-effects.js:50-54`, branche sans créature de `sacrificeOrDamage` ; la mutation ligne 53 est une perte de vie directe.
- `src/core/effects/token-historical-effects.js:112-116`, `lifeLossPerSwamp` ; ligne 115 = perte de vie directe.
- `src/core/effects/upkeep-cost-effects.js:28-33`, `damage()` utilisé pour le coût d'entretien ; ligne 29 = perte de vie directe.

Ils ne doivent pas être routés artificiellement dans le pipeline de prévention des dégâts : une perte de vie directe n'est pas une blessure et ne doit pas être prévenue par une protection ou un bouclier de prévention des dégâts.
