# MoxToGame v12.64 — AUDIT-03 — Rapport de livraison

## Statut

**MISSION TERMINÉE — VALIDÉE**

Objet : utiliser la couleur effective de la source lors des vérifications de protection contre une couleur.

## Preuve de reproduction avant correction

Le test `tests/test-v12-64-protection-couleur-effective-source.mjs` a été créé puis exécuté avec les trois chemins remis temporairement dans leur état antérieur.

Résultat avant correction : **échec confirmé** sur le scénario de combat :

```text
AssertionError: protection from effective blue must prevent damage
2 !== 0
```

La source était imprimée rouge (`R`) mais changée en bleu (`U`) par un effet continu de layer 5. Avec l'ancien code, `combat.js` consultait `source.color` (`R`) et la protection contre `U` ne s'appliquait donc pas.

## Correction

### 1. `src/core/combat.js` — ligne ~141

Avant :

```js
hasProtectionFromColors(this.getState(), target, source?.color || [])
```

Après :

```js
hasProtectionFromColors(this.getState(), target, effectiveTypes(this.getState(), source).color)
```

L'import de `effectiveTypes` a été ajouté depuis `continuous-effects.js`.

### 2. `src/core/effects/atomic-effects.js` — lignes ~151 et ~466

Deux appels identiques supplémentaires ont été trouvés lors de la recherche exhaustive de `hasProtectionFromColors` dans le périmètre autorisé.

Avant :

```js
ctx.api.hasProtectionFromColors(p, colors)
api.hasProtectionFromColors(p, sourceCard.color || [])
```

Après :

```js
ctx.api.hasProtectionFromColors(p, effectiveTypes(ctx.state, ctx.sourceCard).color)
api.hasProtectionFromColors(p, effectiveTypes(state, sourceCard).color)
```

L'import de `effectiveTypes` a été ajouté.

Ces deux chemins concernent respectivement les effets de dégâts à toutes les créatures et les dégâts aux créatures avec le vol. Ils doivent donc eux aussi utiliser la couleur effective de leur source.

### 3. `src/core/replacement-effects.js` — ligne ~78

Avant :

```js
hasProtectionFromColors(this.getState(), target, color ? [color] : (source?.color || []))
```

Après :

```js
hasProtectionFromColors(this.getState(), target, color ? [color] : effectiveTypes(this.getState(), source).color)
```

L'argument `color` explicitement fourni reste prioritaire ; seul le fallback dérivé de `source` utilise désormais la couleur effective.

## Pourquoi `continuous-effects.js` n'a pas été modifié

`hasProtectionFromColors()` utilise déjà `effectiveKeywords(state, permanent)` pour déterminer la protection du permanent protégé. Le défaut se trouvait uniquement chez les appelants, qui transmettaient une couleur statique de source.

La fonction `effectiveTypes()` existante calcule les caractéristiques après les couches continues, dont la layer 5 :

```text
calculateCharacteristics()
  → layer 5
  → changeColor
  → effectiveTypes(...).color
```

Aucune modification de `continuous-effects.js` n'était donc nécessaire ni autorisée.

La base contient un effet `changeColor`, et le moteur implémente explicitement ce mécanisme en layer 5. Aucun Painter's Servant n'est nécessaire pour reproduire le défaut : le test utilise un effet continu synthétique minimal afin d'isoler le contrat du moteur.

Aucune définition de carte n'a été modifiée.
