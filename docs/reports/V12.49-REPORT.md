## Base

## Vérification Oracle

- **Vampire Bats (Legends)** : `{B}: Vampire Bats gets +1/+0 until end of turn. Activate this ability no more than twice each turn.` → limite **2**. Sources consultées : EchoMTG/Deckbox/mtg.wtf, concordantes. citeturn1search1turn1search2turn1search3
- **Fire Drake (The Dark)** : `{R}: Fire Drake gets +1/+0 until end of turn. Activate this ability only once each turn.` → limite **1**. Sources consultées : EchoMTG/MTGGoldfish/MTGNexus, concordantes. citeturn1search0turn1search16turn1search14

Le champ retenu est **`maxPerTurn`**, en camelCase comme les autres propriétés de capacité (`cost`, `tap`, `effect`). Il est normalisé dans `normalizeAbility()` et reste absent (`null`) par défaut afin de ne créer aucune limite implicite.

## Mécanisme implémenté

1. `normalizeAbility()` expose `maxPerTurn`.
2. `isAbilityLegal()` refuse une activation lorsque le compteur du permanent pour cette capacité atteint `maxPerTurn`.
3. Le compteur est stocké **sur le permanent**, dans `activationUsesThisTurn`, indexé par l'identifiant de capacité. Il suit donc l'objet permanent plutôt que son contrôleur.
4. Après une activation effectivement poussée sur la pile, `recordAbilityActivation()` incrémente le compteur.
5. `resetTurnCounters()` réinitialise les compteurs des permanents contrôlés par le joueur qui commence son tour. Ce point d'ancrage est le mécanisme existant de début de nouveau tour ; aucune logique de phase/priorité n'a été modifiée.
6. `createPermanent()` initialise le conteneur du compteur.

Ainsi, un permanent volé pendant un tour conserve son compteur pour ce tour ; il est réinitialisé lorsque le joueur qui le contrôle commence son propre tour. Aucun compteur n'est lié durablement à l'ancien contrôleur.
