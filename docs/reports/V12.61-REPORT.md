# MoxToGame v12.61 — AUDIT-06 REPORT

## Mission
**AUDIT-06 — Paiement de coût de vie exactement jusqu'à 0**

## Correction
Une seule ligne du fichier `src/core/costs/cost-system.js` a été modifiée.

- Ancien comportement (ligne 58) :
  `if (cost.life > 0 && side.life <= cost.life) return false;`
- Nouveau comportement (ligne 58) :
  `if (cost.life > 0 && side.life < cost.life) return false;`

La condition refuse désormais uniquement un paiement lorsque le joueur possède
strictement moins de points de vie que le coût. Un joueur possédant exactement
le nombre de points de vie requis peut donc payer et atteindre 0 PV.

Aucun fichier moteur autre que `cost-system.js` n'a été modifié.
Le test demandé a été ajouté dans `tests/test-v12-61-life-cost-exact-zero.mjs`.

## Test de reproduction avant correction
Commande :

```text
node tests/test-v12-61-life-cost-exact-zero.mjs
```

Résultat avant modification : **ÉCHEC attendu**.

Le premier scénario, joueur à 3 PV avec un coût de 3 PV, retournait :

```text
AssertionError [ERR_ASSERTION]: Un joueur à exactement N PV doit pouvoir payer un coût de N PV.
false !== true
```

Cela confirme directement le bug décrit par la mission.

## Validation après correction

### Scénario 1 — paiement exact jusqu'à 0
- Joueur : 3 PV.
- Coût : 3 PV.
- `canPay()` : **true**.
- `pay()` : PV passent de **3 à 0**.
- Le paiement seul ne marque pas encore la défaite.
- `stateBasedActions.check()` : produit `playerLost` avec raison `zeroOrLessLife` et
  `player.hasLost === true`.

### Scénario 2 — insuffisance
- Joueur : 2 PV.
- Coût : 3 PV.
- `canPay()` : **false**.
- Les PV restent à **2**.

Commande :

```text
node tests/test-v12-61-life-cost-exact-zero.mjs
```

Résultat :

```text
OK V12.61 — coût de vie exactement à 0 autorisé ; insuffisance toujours refusée.
```
